# Design Principles

1. **Evidence before autonomy.** Authority should follow demonstrated capability rather than model branding or vendor claims.
2. **Configuration is the subject.** Capability belongs to a model + harness + instructions + tools + context configuration, not merely a model name.
3. **Risk is contextual.** A strong general coding score does not imply authority for security, authorization, migrations, or high-blast-radius work.
4. **Deterministic evidence first.** Tests, static analysis, policy checks, and other deterministic verification should outrank model self-assessment.
5. **Humans are valid executors.** The data model should not require the executor to be an AI system.
6. **No forced SDLC migration.** Adoption must not require changing coding agents, providers, CI, issue trackers, or development methodology.
7. **Reuse community infrastructure.** The project owns assurance semantics, not commodity execution, policy, telemetry, or provenance infrastructure.
8. **Portable records.** Evidence and capability records should be usable by tools other than the tool that generated them.
9. **Qualification can expire.** Material changes to model, harness, tools, instructions, or environment may require re-evaluation.
10. **Observe before enforce.** Early adoption should produce advice before blocking engineering workflows.
